# 第四步：文档导入与检索

日期：2026-10-09。当前实现阶段：资料导入、基础检索和引用问答。

## 如何使用

运行数据库后，在项目根目录执行 `npm run db:migrate`，创建 documents 和 document_chunks。启动项目并登录，页面出现“我的知识文档”。

选择 UTF-8 的 .txt 或 .md 文件（不超过 400 KB），检查标题和内容后点击保存。也可以直接粘贴文本。后端限制内容 200000 字符，每个片段 800 字符，重叠 100 字符。

输入关键词，例如“报销材料”，点击检索，结果显示文档名、段号和实际原文。没有匹配时明确提示资料不足。当前只检索自己导入的资料，尚无团队共享权限。

## 原理与局限

数据库存储资料与切分结果；检索把中文拆成相邻二字词，把英文拆成词项，计算片段命中数量，返回最多 5 个片段。查询使用参数化 SQL，并在查询内限定当前用户。

这种方式适合先理解检索流程，有词项重合不代表答案充分；同义词、长问题和语义匹配效果有限。它不是向量检索。聊天区域默认“文档问答”，只传入当前用户检索到的片段，要求模型用 [1] 等编号引用。普通对话不读取文档。

保存资料后选择“文档问答”，问“报销材料有哪些”。回答下方展开编号来源，查看文档名、段号和原文；刷新后原文快照仍保留。无匹配时直接提示资料不足，且不会调用模型。有匹配但证据不足时要求模型明确拒答；目前没有自动验证每个结论和引用的语义一致性，仍需查看原文确认。

最新进展：固定评测已实现，并增加有限词组扩展；手动搜索与文档问答复用同一检索函数。原始词项匹配计 2 分，扩展词项匹配计 1 分。没有引入向量模型，详见 [同义问法检索改进](09-同义问法检索改进.md)。

## 验证

运行 `npm run test:db` 验证资料命中、无结果和跨用户隔离；运行 `npm run typecheck` 与 `npm run build` 验证前后端源码。PDF、Word、文档删除、版本管理、团队共享和生产部署尚未实现。

本次类型检查、构建和自动化测试通过，引用快照可随历史恢复。真实供应商引用问答测试发生 120 秒超时，随后短请求也未完成；目前尚不能认定真实引用回答稳定可用。失败状态与来源保存已验证，浏览器引用展开和取消流程仍待端到端验收。

继续排查结果：Responses 短资料问答成功，项目协议已切换为 responses；但完整检索问答仍在 120 秒超时。短请求成功不足以证明完整流程可用，当前需核实供应商接口参数兼容性。为避免不必要的费用，本次不再重复发起真实请求。

最新验证：显式设置 `LLM_REASONING_EFFORT=low` 和 `LLM_MAX_OUTPUT_TOKENS=1024` 后，完整检索问答在 4633 ms 成功返回“报销材料必须包括发票和审批记录。[1]”，来源快照和答案均可从数据库历史读取。此前失败记录保留作为排查过程。不能断定单一参数是超时根因，也不能从单次成功推断整体成功率。

本机 .env 已补充这两项配置；Responses 为当前协议。输出上限允许 256～8192，推理强度允许 low、medium、high，非法值会拒绝调用。修改环境变量后重启后端。后续建立固定问题集验证命中、拒答和引用语义。
