# 同义问法检索改进

本步让已有资料更容易被不同表达找到。题库没有改动，离线结果从 7/8 提升到 8/8；这是小范围检索改进，不代表完整语义理解。

## 原先为什么找不到

用户问“买东西之后要在几日以内递交凭证？”，报销资料写“消费后七天内提交报销申请”。原检索只检查中文二字词是否出现在原文中。它无法自动知道“买东西”可能对应“消费”、“递交”可能对应“提交”。

本步先采用可解释、可在本地验证的词组表，不需要新的模型配置或数据库迁移。

## 请求如何处理

1. 从原问题提取中文二字词及英文词，原始词项最多 40 个。
2. 仅当问题出现完整词组时，加入同组表达的词项，去重并排除已有词项；新增词项最多 40 个，不递归扩展。
3. 在当前用户的文档片段中查找这些词项；每个原始词项匹配计 2 分，每个扩展词项匹配计 1 分。
4. 按分数、文档创建时间、片段位置和片段 ID 排序，返回前五条。分数只是词项匹配分，不是答案正确率或置信度。
5. 手动搜索和文档问答都调用 `retrieve`；问答仍保留原问题，模型依据检索到的原文回答，来源快照仍保存到数据库。

| 可触发的词组 | 扩展范围 |
| --- | --- |
| 消费、购买、买东西 | 同组其他表达 |
| 提交、递交、上交 | 同组其他表达 |
| 请假、休假 | 同组其他表达 |

例如“买东西……递交……”增加“消费、购买、提交、上交”等匹配词项，能够命中报销原文。仅出现“快递”不会因为含“递”而扩展为“提交”。原词权重更高，搜索“购买”时直接写有“购买”的片段优先于仅通过“消费”匹配的片段。

这些词在具体业务中可能有不同含义，扩展会带来额外结果。例如“休假”不一定等同于所有“请假”制度。它只帮助找到候选资料，不能把候选资料当作回答依据已经充分。

## 改了哪些代码

- `apps/server/src/knowledge.ts`：词组扩展、匹配权重、稳定排序，以及搜索入口复用。
- `apps/server/src/evaluation.ts`：报告记录检索版本 `lexical-expansion-1` 和每道题的原始/扩展词项。
- `apps/server/src/knowledge.integration.test.ts`：使用真实 PostgreSQL 验证新问法、排序、接口一致性和隔离。

浏览器页面及接口返回字段保持兼容。开发后端使用 tsx watch 会自动加载源码变更；如果以生产构建启动，需重新构建后重启服务。
