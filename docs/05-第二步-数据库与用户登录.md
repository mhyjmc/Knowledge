# 第二步：数据库与用户登录

更新时间：2026-10-09（北京时间）。

## 这一阶段做成了什么

页面支持注册、登录、刷新恢复登录状态和退出。账号与登录会话保存在真实 PostgreSQL 中，不存于浏览器 localStorage 或服务端内存。

数据库准备了对话表，并提供只读取当前用户对话的接口。当前还没有创建对话和调用模型的功能，下一步实现。

## 本机启动方式

第一次先安装依赖并生成本机配置：

```powershell
cd D:\zhxzzz\team-knowledge-assistant
npm install
npm run db:setup
```

`db:setup` 创建 `.env`，包含随机数据库密码；已有文件会保留。不要分享或提交 `.env`。

当前机器 Docker Desktop 已更新为 4.94.0，但其引擎仍无法启动。因此本步已验证的方式是本地 PostgreSQL 17：

```powershell
npm run db:local
```

保持数据库终端打开，另开终端：

```powershell
cd D:\zhxzzz\team-knowledge-assistant
npm run db:migrate
npm run dev
```

打开 http://127.0.0.1:5173/，在“团队账号”区域注册自己的测试账号。密码至少 10 字符；注册后使用同一邮箱与密码登录。当前没有邮箱验证、找回密码或邀请加入团队功能，请使用学习用密码。

后续启动只需要运行数据库和前后端服务。迁移可重复执行，已经执行的版本会跳过。只修改 `.env` 时，需重启后端；仅数据库重新启动时，连接池会重新建立连接。

## Docker 方式

引擎正常后可以使用：

```powershell
npm run db:up
npm run db:migrate
```

Docker 与本地 PostgreSQL 使用相同端口 5433，不能同时启动。两种方式拥有不同的数据目录：Docker 使用命名数据卷，本地使用 `.local-postgres/`。切换方式不会自动搬迁账号，需要数据库备份/恢复。不要为了切换删除原数据。

`npm run db:stop` 只停止 Docker 容器，不清空数据；本地方式在数据库终端 Ctrl+C 停止。不要删除 `.local-postgres/`，也不要运行 `docker compose down -v`，否则会丢失对应数据库的数据。

## 如何理解后端登录

1. 注册：后端校验邮箱、姓名与密码，将密码加随机盐后用 scrypt 计算摘要，写入 users。
2. 登录：后端重新计算密码摘要并比较，成功后生成随机登录 Token。
3. 保存会话：数据库只保存 Token 的 SHA-256 摘要与过期时间，浏览器保存 HttpOnly Cookie。
4. 身份验证：浏览器请求自动带 Cookie，后端查有效会话，返回对应用户。刷新页面时调用 `/api/auth/me` 恢复登录状态。
5. 退出：删除数据库会话，并让浏览器清除 Cookie。旧 Cookie 此后无法继续访问。

数据库会话有效期为 7 天。HttpOnly 防止普通前端脚本读取登录 Token，SameSite 减少跨站发送风险。修改状态的请求还要求 `X-Requested-With: team-kb` 和可信来源；开发代理下通过明确的 APP_ORIGINS 配置检查前端来源。

## 表结构与接口

| 表 | 作用 |
| --- | --- |
| schema_migrations | 记录执行过的迁移版本 |
| users | 账号、邮箱唯一约束、姓名、密码摘要 |
| auth_sessions | 会话摘要、用户外键、过期时间 |
| conversations | 对话归属、标题，下一步写入消息数据 |

| 接口 | 用途 |
| --- | --- |
| GET /api/database | 检查数据库和迁移是否就绪 |
| POST /api/auth/register | 注册，成功 201，重复邮箱 409 |
| POST /api/auth/login | 登录，错误密码 401 |
| GET /api/auth/me | 当前用户，未登录 401 |
| POST /api/auth/logout | 退出，销毁当前会话 |
| GET /api/conversations | 当前用户的对话，未登录 401 |

SQL 中的 `$1`、`$2` 是参数占位符，不通过拼接用户输入构造 SQL。`WHERE user_id=$1` 保证用户只能读取自己的对话。正式团队文档的角色与权限管理仍在后续阶段。

## 验证方式

```powershell
npm run typecheck
npm test
npm run test:db
npm run build
```

`npm test` 不需要数据库；`test:db` 需要数据库已启动，并使用随机邮箱创建测试用户，结束后只清理这些测试用户及其会话。验证重复注册、错误密码、未登录访问、跨站来源、用户隔离、会话过期和退出失效。

独立数据库连接验证了写入数据可被读取。浏览器验证了真实注册、登录、刷新恢复及退出；完整电脑重启后的恢复尚未验证，数据目录已配置持久化。

## 重点代码

- `apps/server/src/database.ts`：环境变量、连接池、事务迁移和表结构。
- `apps/server/src/auth.ts`：密码处理、Cookie、登录会话和数据隔离。
- `apps/web/src/AuthPanel.vue`：表单、错误提示、登录状态恢复。
- `apps/server/src/auth.integration.test.ts`：真实数据库集成测试。
- `scripts/local-db.mjs`：开发用数据库启动。

## 部署边界

当前只监听本机。部署时必须配置 HTTPS、`COOKIE_SECURE=true`、真实 `APP_ORIGINS`、受限数据库账号和生产数据库连接；多实例登录限流需要共享存储。目前注册开放，仅适合本地学习，公开部署前还需邀请码或管理员控制、邮箱验证及账号恢复。
