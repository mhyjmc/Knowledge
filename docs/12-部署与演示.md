# 部署与演示

本项目提供两种运行方式：本机学习使用 `npm run dev`，Docker 生产演示使用 `compose.production.yaml`。生产镜像包含编译后的 Node.js API 和 Nginx 静态前端；服务端启动时会自动执行已提交的数据库迁移。

## Docker 生产演示

要求 Docker Desktop 引擎可以正常启动。当前开发机曾因 WSL 问题无法启动引擎，因此这里只完成配置与静态构建检查，不能把本机 Docker 启动称为已验收。

1. 复制部署配置并编辑：

```powershell
Set-Location D:\zhxzzz\team-knowledge-assistant
Copy-Item deploy/.env.production.example deploy/.env.production
```

生成并填写随机数据库密码与模型密钥。`deploy/.env.production` 已被忽略规则覆盖，不要提交。生产域名部署时把 `APP_ORIGINS` 改为实际 HTTPS 地址，并设 `COOKIE_SECURE=true`；不要把 API 密钥放入前端或 Dockerfile。

2. 启动并等待健康检查：

```powershell
npm run prod:up
```

打开 http://127.0.0.1:8080 。Nginx 将 `/api/` 转发到内部 Node.js 服务，PostgreSQL 不暴露宿主机端口。服务启动自动运行迁移，首次启动可能需要构建镜像和下载依赖。

3. 查看日志或停止：

```powershell
npm run prod:logs
npm run prod:down
```

`prod:down` 停止容器但保留 Docker 卷；不要使用 `docker compose down -v`，除非明确要删除数据库数据。正式环境还应配置 HTTPS 终止、备份、日志收集、资源限制、密钥管理和数据库监控。

## 本机运行

Docker 不可用时：

```powershell
npm install
npm run db:setup
npm run db:local
```

保持数据库终端运行，再开另一个终端：

```powershell
npm run db:migrate
npm run dev
```

打开 http://127.0.0.1:5173 。服务端现在启动时也会执行迁移，单独运行 `db:migrate` 仍可用于显式检查。生产构建检查：

```powershell
npm run typecheck
npm test
npm run test:db
npm run build
```

## 演示顺序

用独立演示账号完成以下流程，不使用真实员工资料：

1. 注册并登录，确认页面显示 PostgreSQL 已连接。
2. 导入 `docs/fixtures/浏览器验收报销制度.md`，保存后搜索“买东西之后要在几日以内递交凭证”。
3. 切换“文档问答”，提问“报销材料有哪些？”，展示带 `[1]` 的回答并展开原文。
4. 刷新页面，展示会话与来源仍能恢复；再测试无资料问题，说明服务端直接拒答且未调用模型。
5. 在任务助手输入“整理报销材料，准备发票和审批记录”，展示草稿，说明模型只能提议。
6. 点击确认创建待办，展开执行过程，刷新后展示待办仍在。
7. 最后退出账号，确认知识库、聊天和任务面板隐藏。

真实模型调用可能产生费用；演示前优先使用固定合成资料，减少问题数量，不要自动重试。展示供应商 Token 时只读页面简明统计，不把完整用量归因 JSON 或密钥投影到屏幕。

## 部署边界

已实现的是单机/小规模演示部署：登录会话、用户隔离、文本资料、词项检索、引用问答和待办确认。尚未实现高可用、对象存储、PDF 解析、向量检索、团队共享、CSRF 双提交令牌、审计导出、自动备份、HTTPS 证书申请和外部任务系统。上线前必须按实际威胁模型补充这些能力。
