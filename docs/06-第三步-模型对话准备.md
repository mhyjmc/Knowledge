# 第三步：模型对话准备

更新时间：2026-10-09。状态：真实模型流式调用与数据库保存已验证；浏览器取消流程尚待验收。

## 本步要做什么

登录后创建对话，发送问题，逐字显示模型回答；支持停止生成、错误提示和刷新恢复历史。消息保存到 PostgreSQL，只有所属用户可读取。使用一个明确配置的模型，不先引入复杂 Agent 框架。

## 接入前需要的信息

1. 服务商名称。
2. API 基础地址，包括服务商要求的路径。
3. 可调用的准确模型名称。
4. 本机配置的 API 密钥。

前三项可以在聊天中确认。密钥只放项目根目录 .env，不发在聊天里，也不写入前端。不要使用 VITE_ 前缀保存模型密钥，因为 Vite 会把这类变量交付给浏览器。

项目根目录 .env 已补充以下配置，密钥需要你本机填写：

```dotenv
LLM_BASE_URL=https://llmtoken.io/v1
LLM_MODEL=gpt-6.1-sol
LLM_API_KEY=只在本机填写
LLM_API_MODE=responses
LLM_REASONING_EFFORT=low
LLM_MAX_OUTPUT_TOKENS=1024
```

以上配置由服务端读取。LLM_API_KEY 必须替换为服务商发给你的密钥，不要照抄说明文字。修改后在原后端终端 Ctrl+C 停止，再执行 npm run dev；如果统一启动器提示已有服务，请先停止原启动终端。

## 实际使用步骤

1. 保持数据库运行，执行 npm run db:migrate 创建消息表。
2. 在本机 .env 填写 LLM_API_KEY，重启后端。
3. 打开 http://127.0.0.1:5173/ 并登录，智能对话区域会显示配置状态。
4. 发送一个简短问题，观察流式回答；刷新会话确认数据库保存。
5. 如果服务商仅支持 Responses，将 LLM_API_MODE 改为 responses 并重启后端。不会自动切换或重复发起收费请求。

已实现 Chat Completions 和 Responses 两种协议，实际服务商对该模型、参数、流式用量的支持需要真实请求核实。没有配置密钥时不会调用供应商，也不会产生演示假回答。

## 当前接口和存储

GET /api/model 只返回模型名、协议和是否配置，不返回密钥。POST /api/conversations 创建属于当前用户的会话；GET /api/conversations/:id/messages 读取历史；POST 同一路径发送消息。浏览器接收按行 JSON 事件 start、delta、error、done。

messages 表记录角色、文本、状态、模型、耗时及供应商返回用量。未完成的回答不会被当作完整回答加入后续上下文。强制终止进程时可能遗留 generating，下一次发送会将其标为 failed；当前没有后台恢复任务。

生成时会使用有限历史，不超过最近 20 条和约 30000 字符；输出限制 2048 Token。中文字符不等于 Token，后续按实际模型优化。取消会中止接收及上游请求，但供应商是否对已生成内容计费按其规则。

## 验证记录

TypeScript 检查与真实数据库集成测试通过。模型在自动化测试中使用测试替身，验证消息持久化、完成/失败、并发拒绝与跨用户隔离；真实供应商调用、停止生成及账单用量尚待密钥配置后的验收。

## 一个问题将经过哪些步骤

1. Vue 提交会话编号和问题。
2. Node.js 检查登录身份和会话归属。
3. 保存用户问题，读取有限长度的历史消息。
4. 服务端 SDK 请求选定模型，向浏览器流式转发结果。
5. 保存助手回答和执行状态；取消或失败时明确记录状态。
6. 刷新页面后，从数据库读取真实历史。

浏览器不直接调用模型服务。当前尚未加入知识库，因此模型回答不能当作公司制度或团队文档依据。

## 验收标准

- 未配置密钥时明确提示，不能显示假回答。
- 登录用户能获得真实模型流式回答。
- 停止生成后终止上游调用，并记录部分回答的状态。
- 网络失败、模型拒绝或超时时显示中文错误，且不把失败记为成功。
- 刷新恢复消息，其他用户无法读取或写入该会话。
- 记录耗时和服务商返回的 Token 用量；没有用量数据时明确说明。
- 类型检查、接口与数据库测试、构建通过；真实模型联通单独验证。
