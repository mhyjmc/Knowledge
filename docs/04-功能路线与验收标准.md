# 功能路线与验收标准

时间仅作为在职学习参考：每周约 10～15 小时，整体可能需要 9～11 周或更久，按实际理解和交付质量调整。

| 步骤 | 要做什么 | 什么条件算完成 |
| --- | --- | --- |
| 01 基础联通 | Vue、Node.js、统一启动与中文文档 | 页面能获取 API；错误可见且可重试；类型检查、接口测试、构建通过 |
| 02 数据库与登录 | PostgreSQL、迁移、用户表、密码散列、鉴权、会话表 | 注册登录可用；数据重启后保留；未登录和越权访问被拒绝；部署配置有说明 |
| 03 模型对话 | 模型 SDK、流式回答、取消、会话记录、超时 | 服务端保存密钥；能真实回答；刷新可恢复会话；取消和错误处理可演示；记录实际耗时与用量 |
| 04 文档知识库 | 先支持文本/Markdown，再扩展 PDF；切分、检索、引用 | 能上传并检索；回答引用真实片段；资料不足时说明；用户不能读取他人无权限文档；固定问题集有结果 |
| 05 任务助手 | 查询工具、报表或待办；执行状态、确认与失败恢复 | 至少完成一个真实任务；写入前可确认/拒绝；失败可定位；重试不产生重复写入；有执行记录 |
| 06 交付 | 效果评测、费用与延迟统计、生产部署、演示材料 | 文档说明完整部署流程；从干净环境复现；演示完整业务流程；报告成功与失败情况 |

## 第二步的本地数据库启动

优先使用 Docker（当前 Docker Desktop 版本已更新到 4.94.0，但本机引擎仍无法启动）：

```powershell
npm run db:setup
npm run db:up
npm run db:migrate
```

如果 Docker Desktop 报“unable to start”或数据库引擎未运行，改用本项目自带的 Windows 本地 PostgreSQL：

```powershell
npm run db:setup
npm run db:local
```

保持该终端打开，再开另一个终端运行 `npm run db:migrate`。`.local-postgres/` 是本地数据目录，已加入 `.gitignore`。停止时在数据库终端按 Ctrl+C。它适合本机学习；部署时使用 Docker 或托管 PostgreSQL。

## 数据库阶段的学习重点

连接数据库、参数化 SQL、表与关系、唯一约束、数据库迁移、事务、连接池与数据隔离。先解决真实持久化，再加入更多业务功能。

## 模型接入前需要的信息

模型供应商、服务端 API 地址、可用模型名称和 API 密钥。密钥保存在本机服务端环境文件或部署环境变量中，不写进文档、Git 或前端构建。供应商未确定前不伪造真实模型调用结果。

## RAG 与 Agent 的区别

RAG 负责找到资料，辅助模型回答。Agent 负责选择和调用工具，推进任务。流程明确的步骤先用固定工作流，只有需要动态选择动作时再加入更复杂的 Agent 编排。

## 项目最终展示内容

准备源码、可运行演示、项目架构与部署说明、固定测试问题、效果/费用/延迟数据、失败案例及处理方式。能够讲清楚一个真实请求如何从页面经过后端、数据库和模型返回结果。
