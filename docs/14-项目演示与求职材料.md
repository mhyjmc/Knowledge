# 项目演示与求职材料

这份文档把当前项目整理成一次可复述的交付。目标不是背 API，而是能够说明一个问题如何经过前端、后端、数据库、检索和模型，再由用户确认后写入待办。

## 一句话介绍

团队知识库助手是一个 Vue 3 + TypeScript、Fastify、PostgreSQL 和 OpenAI 兼容模型构建的 AI 应用：用户导入自己的制度资料，助手检索原文并带引用回答；当用户描述待办时，模型只生成草稿，用户确认后服务端在事务中创建待办并记录执行事件。

## 5 分钟演示顺序

1. 启动本地 PostgreSQL 和 `npm run dev`，打开 `http://127.0.0.1:5173/`。
2. 注册一个演示账号，说明 Cookie 会话、用户过滤和数据库状态。
3. 上传 `docs/fixtures/浏览器验收报销制度.md`，搜索“买东西之后要在几日以内递交凭证”，展示有限词组扩展后的命中。
4. 使用“文档问答”询问“报销材料有哪些？”，展示 `[1]` 引用，展开查看实际片段。
5. 刷新页面展示历史消息和来源快照仍存在；询问“火星飞船燃料配方”，展示资料不足且未调用模型。
6. 在任务助手输入“整理报销材料，准备发票和审批记录”，展示模型草稿，强调模型尚未写入数据库。
7. 点击确认创建待办，展开事件时间线并刷新，展示待办持久化；最后退出登录。

真实模型演示只使用少量固定合成资料和少量问题，不自动重试。供应商请求可能产生费用，页面只展示简化 Token 统计。Docker Desktop 当前因 BIOS 虚拟化关闭暂缓，演示先使用本地 PostgreSQL；恢复后可按 Docker 排障文档执行 Compose。

## 架构讲解

```text
Vue 页面
  -> Vite 代理 / Nginx
Fastify API
  -> Cookie 会话 + 用户权限
  -> PostgreSQL（用户、会话、消息、文档片段、任务事件）
  -> OpenAI 兼容模型（服务端密钥）
```

文档问答路径是：当前用户问题 → 词项与有限同义扩展 → PostgreSQL 前五个片段 → 带编号的来源快照 → Responses 流式输出 → 消息与用量保存。没有片段时后端直接返回资料不足，不请求模型。

任务路径是：需求 → 模型严格 JSON 草稿 → 数据库 `pending` → 用户确认 → 事务插入 `tasks` 与 `executed` 事件。`requestId` 和行锁避免重放及并发确认重复写入。

## 常见面试追问

**为什么没有直接让模型写数据库？** 模型输出不可信，先保存 `pending` 草稿，让用户明确确认；确认接口只读取数据库中的草稿，客户端不能替换标题或说明。

**如何避免重复创建待办？** 生成请求使用用户范围内唯一 `requestId`；确认时锁定 `task_runs` 行，重复确认返回既有任务，插入任务和事件在同一个事务中完成。

**资料不足怎么处理？** 检索为空时服务端直接返回固定拒答，不调用模型；检索有片段但证据不足时通过系统指令要求模型拒绝补全，并保存来源快照供人工检查。

**为什么不是向量检索？** 当前先用可解释、无需额外 embedding 服务的词项检索和有限扩展，固定题库可回归；同义范围有限，后续选择 embedding 服务后再比较召回和误召回。

**密钥放在哪里？** 只在服务端环境变量，前端 `/api/model` 只返回模型名和配置状态，不返回密钥。

**现在的不足是什么？** Docker 因本机 BIOS 虚拟化暂缓；尚无 PDF 解析、向量检索、团队共享、外部任务系统、备份和高可用；部分正文后的取消场景仍未验收。
