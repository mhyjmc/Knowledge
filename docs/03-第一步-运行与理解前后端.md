# 第一步：运行与理解前后端

## 一、本步学习目标

你已有 Vue / React 经验，这一步重点理解：浏览器请求如何到达你写的 Node.js 服务，以及如何验证后端是否正常。

暂时不需要模型账号、API 密钥或数据库。

## 二、启动方法

Windows 快速方式：双击 D:\zhxzzz\team-knowledge-assistant\start.cmd，然后访问 http://127.0.0.1:5173/。启动窗口需要保持打开。已有前后端服务时会提示“已经在运行”。

打开 PowerShell，依次执行：

```powershell
Set-Location D:\zhxzzz\team-knowledge-assistant
npm install
npm run dev
```

第一次需要安装依赖。已有 package-lock.json 后，也可以使用 npm ci 按固定版本重新安装。npm run dev 会同时启动两个服务：

| 地址 | 含义 |
| --- | --- |
| http://127.0.0.1:5173 | Vue 页面 |
| http://127.0.0.1:3001/api/health | Node.js 健康检查 API |
| http://127.0.0.1:3001/api/project | 项目名称、阶段与功能状态 |

打开页面应显示“前后端已连接”。打开健康检查地址会看到 JSON，例如 status 是 ok。结束运行按 Ctrl+C。

## 三、一次请求经过了什么

1. App.vue 挂载时调用 connect()。
2. fetch('/api/project') 向前端开发服务器发送请求。
3. vite.config.ts 的 proxy 把 /api 请求转发给 3001 端口的后端。
4. app.ts 中的 Fastify 路由返回项目 JSON 数据。
5. Vue 把响应保存到 ref，更新页面连接状态与开发路线。

开发代理帮助浏览器用同一个来源访问 API。正式部署时需要配置反向代理或其他明确的 API 访问方式，不能假设 Vite 开发代理仍然存在。

## 四、重点阅读的文件

| 文件 | 需要理解的内容 |
| --- | --- |
| apps/web/src/App.vue | 异步请求、加载/错误状态、重试和响应渲染 |
| apps/web/vite.config.ts | 前端请求如何代理到后端 |
| apps/server/src/app.ts | 一个 HTTP 路由如何返回数据 |
| apps/server/src/index.ts | 服务如何启动与停止 |
| apps/server/src/app.test.ts | 不启动端口也能验证 API |
| 根目录 package.json | workspaces 与统一脚本 |

后端与前端不同：后端运行在服务器，可以访问数据库、保存密钥和验证身份；前端代码会交付给浏览器。模型密钥必须放在后端。

## 五、验证命令

Windows 可以双击项目根目录的 check.cmd，它会自动进入正确目录，依次运行类型检查和接口测试，并保留窗口。两个退出码都是 0 表示通过。

在项目根目录运行：

```powershell
Set-Location D:\zhxzzz\team-knowledge-assistant
npm run typecheck
npm test
npm run build
```

如果 PowerShell 报 npm.ps1 无法运行，可改用 npm.cmd run typecheck 和 npm.cmd test。报错含 ENOENT / package.json 时，先检查是否在项目根目录；报错含 Missing script: test 时，确认没有进入仅包含前端代码的 apps/web 目录。

类型检查验证 TypeScript 与 Vue 类型；接口测试验证 HTTP 状态和返回内容；构建验证源码能生成生产文件。这些检查通过也不代表数据库或模型功能已实现。

## 六、你可以亲手做的练习

将 app.ts 返回的 stage 改成自己想显示的中文描述，保存后观察页面刷新结果。这个练习能让你确认页面内容来自后端，而不是写死在 Vue 模板中。

另开终端单独启动前端、暂不启动后端，观察失败提示；再启动后端，点击重新检查连接。先结束统一启动的服务，避免端口占用：

```powershell
npm run dev -w @team-kb/web
```

另一个终端运行：

```powershell
npm run dev -w @team-kb/server
```

## 七、常见问题

- 5173 或 3001 已被占用：统一启动命令会检测已有服务，完整运行时显示访问地址；仅部分服务在运行或其他程序占用时显示中文报错。先在自己原来的启动窗口按 Ctrl+C，再重试。若必须换端口，需要同时调整启动检查、前端服务配置、代理与后端 PORT。
- 显示 Missing script: dev：可能在 D:\zhxzzz 或其他项目目录执行了命令；先进入 team-knowledge-assistant，或直接双击 start.cmd。
- 直接打开 index.html 后页面空白：Vue 项目需要开发服务器，请按本节启动，使用 5173 地址访问。

第二步数据库若需要先启动：优先执行 `npm run db:setup`、`npm run db:up`；Docker Desktop 无法启动时执行 `npm run db:local`。数据库终端必须保持打开，另一个终端再执行 `npm run db:migrate`。
- 无法连接后端：查看终端错误，直接打开 /api/health 确认后端是否运行。
- npm 命令无法执行：确认 Node.js 和 npm 已进入 PATH；PowerShell 执行策略限制 npm.ps1 时，可使用 npm.cmd 执行相同命令。
- 安装失败：保留错误信息，先检查网络与 Node.js 版本。
